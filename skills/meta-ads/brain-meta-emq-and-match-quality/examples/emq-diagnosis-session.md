# Worked example: diagnosing a Lead EMQ of 5.2

A hypothetical but representative session showing this brain applied end-to-end.
The scenario is invented for illustration; every rule, number and citation comes
from the brain's synthesis and quote library.

---

## The ask

> "Our Lead EMQ is 5.2 and cost per lead has crept up over the last month.
> The pixel is firing fine. What's wrong?"

## Step 1: Confirm a score exists, then read the bands

A score of 5.2 means CAPI is at least sending something. Jack Newman's rule:

> "you have to have the conversions API to be sending back that serverside data if you want to show your EMQ score." - Jack Newman

If the score were missing entirely, the diagnosis would stop here and go to
server-side delivery first (see the first IF/THEN rule in SKILL.md).

5.2 sits in SignalBridge's 4-6 "partial" band, below the 6.0 floor and well short
of the 7+ target. Since a score exists at all, server events are arriving and this
is a thin-payload problem, so the working hypothesis is missing match keys rather
than a broken pixel or a dead server rail.

## Step 2: Open the Event Quality tab and log the baseline

Events Manager > pixel > the Lead event > View Details > Event Quality.
Record the per-parameter coverage before touching anything. In this scenario:

| Parameter | Coverage | Read |
|---|---|---|
| IP address | 98% | Fine, technical params should sit 95%+ (TrackingFixes) |
| User agent | 97% | Fine |
| FBP (browser ID) | 96% | Fine, auto-generated by the base pixel |
| FBC (click ID) | 31% | Problem. Should be high on paid traffic |
| Hashed email | 0% | Problem. The single highest-impact key is absent |
| Hashed phone | 0% | Problem |

The table does the diagnosis for you: the event is riding on technical
parameters only. That matches the SignalBridge stacking ladder, where an
IP-plus-basics event sits in the 2-3 to 5-6 range until personal keys arrive.

## Step 3: Apply the IF/THEN rules in order

1. **Lead EMQ under 6 with no hashed email:** add hashed email first.
   > "Adding hashed email alone can boost your EMQ by 1.5 to two points." - SignalBridge
   Then phone. Email plus phone typically lands the 7-8 range per the same source.
2. **FBC at 31%:** trace the CreatorOpsMatrix FBC chain. Ad click appends the
   fbclid; the landing page must capture and store it; the server event must
   map it to FBC unmodified. In this scenario the landing page was dropping the
   fbclid on redirect, so the chain broke at link two. Fix: persist the fbclid
   on landing and pass it through untouched.
3. **Normalise before hashing:** lowercase and trim the email, format the phone
   E.164, then SHA-256 both. Skipping this is CreatorOpsMatrix's second trap;
   a hashed-but-unnormalised key never matches.
4. **Check dedup while you are in there:** browser and server Lead events must
   share one identical, unique event ID. In Test Events, confirm the same ID
   appears on both sides and Events Manager counts one event. If the platform
   cannot carry a matching ID on both sides, run the Lead event CAPI-only
   (Jack Newman) rather than double count.
5. **Empty beats fake:** any field with no real value sends empty. No
   placeholder emails, no default phone numbers (Pro Data Track).

## Step 4: Ship, then wait out the rolling window

EMQ averages over roughly a 48-hour rolling window plus history, and low
volume slows it further (TrackingFixes). The score will not jump the same day
the fix ships. Do not stack more changes on top while waiting; you lose the
ability to attribute the movement.

## Step 5: Re-check and set the weekly ritual

Seven to ten days later in this scenario: hashed email coverage 94%, FBC 87%,
Lead EMQ 7.6. That is inside the 7+ target band for Lead and Purchase. Expected
movement, not a promised one; the same fixes on a lower-volume account move
slower.

Close out with SignalBridge's weekly 4-step check: open Events Manager, read
the conversion event's EMQ, scan the customer information parameters for
colour changes, investigate any drop the same week. Breaks are silent.

## What made this fast

- The Event Quality tab's per-parameter table located the gap in one look.
- The IF/THEN ladder ordered the fixes by impact (email, phone, click ID).
- Knowing the rolling-window rule prevented a panic revert on day two.
