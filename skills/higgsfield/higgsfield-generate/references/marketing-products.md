# Products and web products

Distinguish an existing product entity, a URL import, and a product assembled from authorized images. A web/app product may use a different field. Preserve supplied labels, packaging and proof; generation is not evidence of actual product behavior.

Inspect help for the selected `marketing-studio products` operation. Official guides describe list, fetch by URL and create from uploaded images. Exact flags, readiness status, response fields and cost must be established for the selected version/account before use.

Reuse a suitable authorized existing entity. A URL fetch sends that URL and may import site content; an image path uploads that file. Do not use private or credential-bearing URLs as import targets. Wait for evidenced readiness before dependent generation, using the root guide's finite bounds.

For manual creation, retain the upload IDs from the intended images and serialize the required arrays correctly. If both product and web-product arrays are mutually exclusive in the selected schema, choose the one matching the actual entity. Do not reinterpret a raw UUID as the other type.

The old guide claimed URL deduplication. That claim does not make imports or subsequent generation generally idempotent. Record the entity returned by the first operation and recover it before any repeat. A Click-to-Ad shortcut must satisfy the same authority, readiness and uncertainty checks as separate import/generation steps.
