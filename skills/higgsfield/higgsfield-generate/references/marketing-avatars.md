# Presenter avatars

Choose a preset or custom presenter from the brief. Preserve a specifically requested identity. Do not invent a real person's likeness or assume selection/upload is free. The selected account, applicable consent and production authority must cover the asset use.

Official guides describe an `avatars` group under `higgsfield marketing-studio`, including list and create. Inspect the installed group's help and selected response schema before using filters or fields. A preset/custom distinction is useful; exact identifiers, enum values and JSON array encoding must come from that version.

For a custom avatar, upload the authorized source once and inspect that one result. Some documented create examples require both an image ID and image URL, but the public material does not prove a stable upload JSON schema containing both. Accept the pair only when evidence binds both fields to the same upload. If the contract is missing, report the unsupported step; do not upload again to obtain another representation or fabricate a field.

Keep token-bearing/signed URLs out of durable logs. A required transient URL may be passed directly to the selected operation within the existing task; record only a safe asset reference afterward.

Bind the selected presenter in the supported generation field and inspect identity consistency in the output. An omitted avatar does not guarantee that the provider creates a suitable or consistent person.
